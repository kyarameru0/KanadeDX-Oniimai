# Translations (i18n)

The module ships English, Korean and Simplified Chinese UI text. Every user-visible
message has a stable key, and each language supplies its own text for that key.
English is the fallback. The game's Android resources and the system locale are
never modified; the module carries its own catalogue.

## Files

| Path | Role |
| --- | --- |
| `locales/en.json`, `locales/ko.json`, `locales/zh-Hans.json` | One flat JSON object per language: `"settings.led.port": "LED port"`. Edit these. |
| `scripts/generate_locales.py` | Validates the three files and generates the two Java files below. |
| `app/src/main/java/io/oniimai/kanade/Msg.java` | Generated `int` constants, one per key (`settings.led.port` → `Msg.SETTINGS_LED_PORT`). |
| `app/src/main/java/io/oniimai/kanade/I18nCatalog.java` | Generated texts. Do not edit either generated file by hand. |
| `app/src/main/java/io/oniimai/kanade/I18n.java` | Runtime: current language, device-language matching, fallback and `{0}` formatting. |
| `UiLanguage.java` | Saves the user's choice (`ui_language`) and shows the language picker. |

## Using a message

```java
row.setText(I18n.t(Msg.SETTINGS_LED_PORT));                 // Java
tell(I18n.t(Msg.USB_ERROR, error));                           // with an argument
```

```kotlin
Text(str(Msg.SETTINGS_TITLE))                                 // Kotlin (OniTheme.kt helper)
Caption(str(Msg.NUMBER_RANGE, min, max))
```

Rules that keep every language correct:

- **One sentence, one message.** Never build a sentence from translated fragments
  (`t(A) + value + t(B)`). Word order differs between languages: the Korean text
  puts the delay before the verb, English says "reconnecting in 4 s". Put the value
  in the message as `{0}` and pass it as an argument.
- **Placeholders are positional** (`{0}`, `{1}` …) and each language may reorder them.
  Apostrophes and other braces are literal; this is not `java.text.MessageFormat`.
- **No hard-coded UI text.** `check_locales.py` rejects Korean or Chinese string literals in
  module sources. Device names, protocol names (`Command · 115200`), numbers and
  units such as `P1 / START` may stay as code literals.
- Keys are dotted lowercase: `area.subject.detail`, for example `display.status.retry_in`.
  Renaming a key is a source change. A key is never reused for a different meaning.

## Adding or changing a message

1. Add the key to **all three** files with a text for each language. Keep `en.json` sorted
   by key; the generator checks the order.
2. Run `python scripts/generate_locales.py`.
3. Use `Msg.YOUR_KEY` in code.
4. Run `python scripts/check_locales.py`. It fails on:
   - a missing key or an empty text;
   - placeholders or line breaks that differ from English;
   - Korean in Chinese or English text;
   - an unused key;
   - a hard-coded Korean/Chinese literal;
   - leftovers of the retired `tr(ko, zh)` / `UiText` helpers;
   - stale generated files.
5. Check the screen in each language. English is usually the longest, and tab labels have
   a fixed width.

## Adding a language

1. Add `locales/<tag>.json` with every key. Use a BCP 47 tag such as `ja`.
2. Add the tag to `LANGUAGES` in `scripts/generate_locales.py` and regenerate.
3. Add its autonym to `I18n.NAMES` (same order as `LANGUAGES`). Extend `I18n.supported()`
   so device tags map to it, `I18n.locale()` for date formatting, and the
   `LANGUAGE_TITLE` string.
4. Update `I18nTest` and run the host suite.

## Language selection

- Without a saved choice, the first supported language in the device's preferred-language
  list is used, otherwise English.
- `zh`, `zh-CN`, `zh-SG` and `zh-Hans-*` map to Simplified Chinese. Traditional Chinese
  tags (`zh-TW`, `zh-HK`, `zh-Hant`) fall back to English: the module has no Traditional
  Chinese catalogue, and showing a different script is not treated as a match.
- The first-run wizard and **Settings → Language** save an explicit choice.
- The language title and the language names are written in their own scripts
  (autonyms), so any user can find their language.

## Checks

`scripts/test.py` runs `I18nTest`. It covers:

- tag matching and fallback;
- formatting and argument order;
- every language and message being present;
- placeholder numbering.

Worker tests that assert on status text select Korean explicitly (`I18n.language("ko")`).
